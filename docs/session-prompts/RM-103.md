# RM-103 — Test `coordination-service.ts`: ranking first, cycle included

**Load:**
- `docs/edrs/EDR-004-coordination-service.md` — the contract, the ranking algorithm, and why the
  BFS shape is deliberate
- `docs/use-cases.md` UC-009 — the behavioural contract this service owes
- `src/services/coordination-service.ts`
- `.claude/standards/testing.md`
- **Do NOT load:** `sync.ts` (that is RM-102), `src/mcp/server.ts`, `docs/chronicle-spec.md`

**Scope:**

771 lines, four concerns, **zero tests**. Test in this order — each step is strictly cheaper than
the next, and the first is a pure function.

1. **`computePriorityRanks` — pure, and therefore first.** Four graph shapes:
   - a linear chain (`A ← B ← C`): rank A = 2, B = 1, C = 0
   - a diamond (two independent paths converging)
   - disconnected components (no cross-contamination of ranks)
   - **a cycle.** EDR-004 says the BFS is written this way *because* it tolerates a cycle where a
     memoised recursion would not. Pin that: a cycle MUST produce finite ranks and MUST NOT hang
     or throw. This test is the reason the implementation cannot be "optimised" later without
     someone noticing.
   It is currently `private`. Prefer testing it through `decomposeWork`; extract it to a module
   only if that proves impossible — and if you extract, that is a `refactor(axon):` commit of its
   own, with no behaviour change (it is also step 1 of RM-401, so coordinate there).
2. **The assignment/availability invariant.** `assignNext` then `completeWork` MUST leave no
   contributor marked `busy` with no active assignment. This is the invariant two tables can
   silently disagree about.
3. **`assignNext` returns `null`** — never throws — when nothing is unblocked, and when no
   contributor matches the required role.
4. **Branch-name derivation**: `feature/<contributor>/<package>`, `merge/<package>` for a
   `merger`, `spec/<package>` for a `specwright`. It is a contract between `assignNext` and
   `resolveMerge`.
5. **Downstream promotion**: `completeWork` promotes every package whose dependencies are now
   all satisfied, and no others.

**NOT IN SCOPE:**

- **Splitting the service.** That is RM-401, and it depends on this task. Tests first, so the
  split is verifiable rather than hopeful.
- **Adding cycle validation to `decomposeWork`.** EDR-004 records the absent acyclicity check as
  accepted for now. Pin the current tolerant behaviour; proposing validation needs an ADR.
- **Making the service compute a gate verdict.** It records one. Enforcement is ForgeCraft's job
  (`.claude/core.md` scope boundary).
- Any `axon` MCP-surface test. That is RM-301, at the boundary.
