# RM-105 — Add `server.json` and publish to the MCP Registry, or strike NFR-08

**Load:**
- `docs/spec.md §5` NFR-08 — *"Published to the MCP Registry (`server.json` in repo root)"*
- `package.json`
- `docs/use-cases.md` UC-008 — the zero-config cold start this publication is supposed to serve
- The current MCP Registry `server.json` schema (fetch it; do not write the file from memory)
- **Do NOT load:** anything under `src/`. This task touches no source.

**Scope:**

NFR-08 is the one row in the NFR table that is not *unrun* but **not met**: `server.json` does not
exist, so the registry publication the spec claims has never happened. A specification that claims
a distribution channel it does not use is a specification a reader cannot trust on anything else.

Decide, and make the repository agree with the decision:

**Either (A) publish.**
1. Fetch the current registry schema. Write `server.json` against it — do not guess field names.
2. Validate it against the schema, not by eye.
3. Submit the registry entry.
4. NFR-08 becomes **verified** with the submission date and the registry URL; a record goes to
   `docs/evidence/`.

**Or (B) strike the claim.**
1. Remove NFR-08 from `docs/spec.md §5`.
2. Add a line to `docs/spec.md §6` under *Genuinely deferred* saying registry publication is not
   pursued, **and why** — a deferral without a reason is a TODO, not a decision.
3. If the reason is a real trade-off (registry listing implies a support expectation, say), that
   is an ADR, not a spec edit.

B is a perfectly good outcome. The defect is the mismatch, not the absence.

**NOT IN SCOPE:**

- Changing the npm publication (NFR-07 is met and verified).
- Version bumping or releasing. This task changes metadata or a spec line, nothing shipping.
- Any other NFR row.
- Writing `server.json` from memory of the schema. Fetch it.

**Acceptance:**

- [ ] Either `server.json` exists, validates against the fetched schema, and the submission is
      recorded in `docs/evidence/` — or NFR-08 is removed and its absence explained in §6
- [ ] `docs/spec.md §5` contains no row that is "not met"
- [ ] `Status.md` no longer says the registry publication has not happened
- [ ] `node scripts/gs-cascade-check.mjs` exits 0

**Commit:** `spec(registry): publish server.json to the MCP Registry` — or —
`spec(registry): strike NFR-08; registry publication is not pursued`
