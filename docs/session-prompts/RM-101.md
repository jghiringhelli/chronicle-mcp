# RM-101 — Run every gate on Node 20 and commit the execution records

**Load:**
- `Status.md` (the *unrun* lines are the work list)
- `docs/gs-assessment.md` — the Evidence table, and P1 item 1
- `.claude/ledger.md` — Known Pitfalls, first two entries
- `.claude/standards/tool-sequencing.md` §4 — the gate order is not arbitrary
- **Do NOT load:** `docs/chronicle-spec.md` (superseded), any EDR, any other roadmap item

**Scope:**

Get every gate to *run* on Node 20 and commit what it printed. This task produces **evidence**,
not improvements.

1. Install Node 20 (`nvm use 20` / `fnm use 20`). `better-sqlite3@11` has no Node 24 prebuild —
   that is the whole reason this item exists and is first.
2. `corepack enable && pnpm install` — the lockfile is stale against `package.json` (the
   coverage-provider pin and the new dev dependencies), so expect to regenerate it.
   Commit the lockfile change as its own `chore(deps):` commit.
3. Run each gate in the order in tool-sequencing §4 and tee every output to `docs/evidence/`
   with the command, the exit code, the timestamp, and the Node and tool versions:
   `cascade` → `typecheck` → `lint` → `test:coverage` → `test:mutation` → `audit:supply-chain`
4. `pnpm run hooks:install`, then verify the hook actually fires on a throwaway commit.
5. Update `Status.md`: replace every *unrun* with the measured result and its record path.
6. Update the Evidence table in `docs/gs-assessment.md` with the same numbers.

**NOT IN SCOPE:**

- **Implementation code in `src/`.** If a test fails for a real reason, record the failure and
  stop. Do not fix it here — a failing test discovered by this task becomes its own item.
- **Writing new tests.** That is RM-102 and RM-103.
- **Lowering a threshold to make a gate pass.** If MSI comes in under 65%, the number is the
  finding. A surviving mutant is an assertion that was not written, never a threshold that was
  set too high.
- **Touching `eslint.config.js` or `stryker.config.json`** except to fix a genuine
  configuration error that stops the tool from starting. A rule that fires is a finding.

**Acceptance:**

- [ ] `docs/evidence/` holds one record per gate, each carrying command, exit code, timestamp,
      Node version and tool version
- [ ] The test suite is green on Node 20, or every failure is recorded with its cause
- [ ] A coverage percentage exists (first time ever — the provider could not load before)
- [ ] A mutation score exists (first time ever)
- [ ] `pnpm audit --prod --audit-level=high` is clean, or each advisory is recorded
- [ ] The pre-commit hook demonstrably fires and demonstrably blocks a deliberate violation
- [ ] No line in `Status.md` reads *unrun*
- [ ] `node scripts/gs-cascade-check.mjs` still exits 0

**Commit:** `chore(gates): run every gate on Node 20 and record the evidence`
