# Session Prompt: RM-004 — JanitorService

## Objective

Implement the JanitorService system (spec §F10): a background memory consolidation process
that uses LLM-based semantic judgment to prune contradictions, merge near-duplicates, and
sanitise stale memories — complementing the mathematical Ebbinghaus decay system.

Inspired by Claude Code's "Auto Dream" feature, but implemented as Chronicle's own
provider-agnostic service so it works regardless of which AI client is in use.

## Acceptance Criteria

- [ ] `JanitorService` port defined in `src/ports/gateways/janitor-service.ts`
  - `run(scope): Promise<JanitorReport>`
  - `getStatus(): JanitorStatus`
  - `isLocked(): boolean`
- [ ] `LLMJanitorService` adapter in `src/adapters/gateways/llm-janitor-service.ts`
  - Exports Buffer+Working memories grouped by type+project
  - LLM pass detects contradictions and near-duplicates
  - Soft-deletes losers (tombstone with reason), merges duplicates
  - Writes `~/.chronicle/janitor-log.json`
- [ ] `WeightOnlyJanitorService` adapter — fallback, no LLM, prunes weight < threshold
- [ ] `AutoDreamJanitorService` adapter — delegates to Claude Code Auto Dream if detected
- [ ] Lockfile at `~/.chronicle/.janitor.lock` (prevents concurrent runs + mid-session runs)
- [ ] Trigger conditions enforced: ≥24h since last run AND ≥5 sessions since last run
- [ ] Architectural + Procedural memories (Core tier, decayRate=0) are NEVER pruned
- [ ] Three new MCP tools: `janitor_status()`, `janitor_run(scope?)`, `janitor_log(limit?)`
- [ ] Unit tests for trigger conditions, lockfile, exempt-type guard, merge logic
- [ ] Integration test: insert 3 contradictory memories → run janitor → verify only 1 remains

## Constraints

- Janitor MUST NOT run while a session lock is active (`~/.chronicle/.session.lock`)
- LLM calls are optional — `WeightOnlyJanitorService` must work with zero API calls
- All deletes are soft (tombstone) for 30 days before hard delete
- No modifications to `src/domain/` entities — janitor operates only via repository ports
