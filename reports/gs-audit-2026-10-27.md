## SECTION 1 — SAVED REPORT CARD

### SELF-DESCRIBING (S) — **B+**

**Finding.** The repository explains itself without its author better than most: a single
authoritative spec, twenty active ADRs, four EDRs, and a sentinel tree whose read budgets are
enforced by a script rather than asserted — but the documents have drifted 47 days behind the code.

**Citation.** `.claude/index.md:4` declares the one door and `.claude/index.md:16-20` routes each task
domain to exactly one node; `.claude/index.md:62-67` lists the tree invariants that
`scripts/gs-cascade-check.mjs` fails the build on, including a 300-line read budget per node and an
`@path` that does not resolve. `docs/spec.md:37` is §0 "Intent and scope boundary", and
`.claude/core.md:19-26` restates the scope boundary as five explicit NOTs.

**Why not an A.** `Status.md` was last committed 2026-09-10 (`8f5afe8`) and its own gate table at
`Status.md:30-44` now contradicts the evidence files it cites — see §5. `docs/PRD.md`,
`docs/TechSpec.md`, `docs/use-cases.md`, `docs/gs-assessment.md`, `README.md` and `CLAUDE.md` all
date to 2026-09-10; the newest `src/` commit is 2026-09-15 and five weeks of ADR, RLS and CI work
followed it.

**Next step to raise it.** Regenerate `Status.md` from the evidence files and make that regeneration
a gate, so a document that disagrees with its own citations fails rather than ages.

**The most under-served layer is integration**, and the repository knows it: the ledger's third

database, because the suite's fake `sql` client returned the shapes the code wanted. The remedy

`scripts/verify-isolation.mjs` constructs a throwaway table carrying the *old vulnerable* RLS policy
and replays the same attack against it, so a pass means the policy held rather than the check having
stopped looking.

**Next step to raise it.** Promote the five `scripts/verify-*.mjs` into `tests/integration/` behind a
tag that is skipped without credentials, so the pyramid states what exists instead of hiding it in

### EXECUTABLE (E) — **B**

**Finding.** A clean clone reaches a running, gated state through declared scripts, and CI runs seven
jobs; but one verification path needs secrets a contributor does not have, and the trigger that used
to carry it was removed four days ago.

**Citation.** `package.json` declares `gates` = `cascade && typecheck && lint && test:coverage &&
deps:policy`, `prepublishOnly` = `release:check && gates && build && smoke`, and
`packageManager: pnpm@10.15.0` with `engines.node >= 22`. `.github/workflows/ci.yml` defines
`cascade`, `verify`, `generative-execution`, `mutation`, `supply-chain`, `benchmark` and
`cloud-verify`. Generative execution is measured, not claimed: `pnpm run smoke` reports 12/12
(`docs/evidence/mcp-smoke.json`).

**Verified live for this audit.** `node node_modules/typescript/bin/tsc --noEmit` → **exit 0, 2 s**.

**Why not an A.** `cloud-verify` is gated on `github.event_name == 'schedule' || workflow_dispatch`
(`.github/workflows/ci.yml:211`), and the `schedule` trigger was removed on 2026-10-26 (commit
`a52a4d7`, PR #7, still open), so that job currently runs only when a human presses it. The
repository is honest about why — the job needs a live Postgres credential and writes to a database a

**Next step to raise it.** Give `cloud-verify` a disposable database so it can run on `pull_request`,
or record in an EDR that end-to-end verification is deliberately manual and who owns running it.

### DEFENDED (D) — **B**

**Finding.** The gates fail the build rather than warn, and the most important boundary in the
system is enforced by Postgres rather than by client code — but two specific gates are advisory
when they should not be, and the team licence check fails open.

**What is genuinely defended.**
- `.githooks/pre-commit:68-73` exits 1 on any failed gate and prints `Do not use --no-verify`.
  Secrets are checked first, "the only check whose failure is unrecoverable once pushed"
  (`.githooks/pre-commit:46`).
- `eslint.config.js:64` makes `import/no-cycle` an **error** with `maxDepth: Infinity`, so the layer
  map in `.claude/core.md:32-37` is enforced, not asserted.
- Row-level security is applied and verified: isolation 15/15, cross-machine sync 16/16, team layer
  9/9 (`docs/evidence/isolation-verify.json`, `cloud-sync-verify.json`, `team-cloud-verify.json`,
  all re-measured 2026-10-26). `prompt_logs` has no `raw_content` or `share_content` column at all —
  ADR-019's reasoning that "a flag that can be flipped is a promise; an absent column is a property".
- No hardcoded credential found in `src/` or `scripts/`: every connection string arrives through
  `process.env` or `~/.chronicle/`, and `process.env` appears only twice in `src/`.

**Gaps.**

1. **`src/mcp/team-gate.ts:28` fails open.** `if (!railwayUrl) { _tokenValid = true; return true; }`,
   and the surrounding doc comment states the intent: "fails open when Railway is unreachable, so
   offline work is never blocked." Convenience is the right trade for a licence check and the wrong
   one for anything that gates data; the file should say which it is. **Rate: Gap.**
2. **`.claude/hooks/pre-commit-function-length.sh:27` is advisory by construction** — the comment
   reads "Warning only — does not block commit since bash heuristics aren't perfect" and the script
   ends `exit 0` unconditionally. Its `WARNINGS=$((WARNINGS + $?))` on line 24 also accumulates
   awk's exit status rather than a count, so the counter it keeps is meaningless. **Rate: Gap.**
3. **`.githooks/commit-msg:16-21` skips its own check when the delegate is missing**: if
   `.claude/hooks/commit-msg.sh` is absent it prints `conventional-commit format unchecked` and
   exits 0. The file is present today, so the gate works; but the failure mode is a silent pass, which
   is the class the ledger's fourth pitfall was written about. **Rate: Gap.**
4. **`prepublishOnly` does not run `pnpm audit`.** It runs `deps:policy`, which is the
   approved-library check, not the advisory check. A publish is therefore not blocked by an open
   advisory. **Rate: Gap** (and the nearest thing in this repository to a release-time hole).

**Next step to raise it.** Close item 4 before v0.5.0: add `audit:supply-chain` to `gates` or to
`prepublishOnly`. It is one line and it is the only one of the four that can ship a known-vulnerable
package.

the two it can. `src/mcp/server.ts:37` at 636 lines is a single registration function; splitting it
per tool group is the one change that moves both this grade and VERIFIABLE, since it is also the

### COMPOSABLE — **B+**

**Finding.** The dependency rule is stated and machine-enforced, and the audit found no cycles.

**Measured live.** `node node_modules/eslint/bin/eslint.js src tests` over **86 files: 0 errors, 43
warnings** — 28 `@typescript-eslint/no-explicit-any`, 15 `@typescript-eslint/no-non-null-assertion`.
Zero `import/no-cycle` violations, which is an error-level rule, so the build would have failed.

**Citation.** `.claude/core.md:32-37` states the layer map and that "Domain imports nothing. Services

recorded exemptions.

**Next step to raise it.** Promote `@typescript-eslint/no-non-null-assertion` to an error — 15 sites,
the smaller half — and give each surviving one an inline exemption naming why the value cannot be
null. That converts 15 silent assertions into 15 recorded claims, and it is the cheapest change that
moves this grade, because the cycle half of the property is already at A.

## SECTION 2 — REPORT CARD SUMMARY

### OVERALL GRADE — **B-** (SAVED), engineering layer **C+**

**Confidence: moderate, and explicitly mixed.** The grades for SELF-DESCRIBING, AUDITABLE, DEFENDED
and COMPOSABLE rest on evidence I read or re-measured during this audit — the eslint and tsc runs are
mine, dated today, and the RLS verifier outputs were re-measured 2026-10-26 after an outage.

**The test suite ran, after this report was first written.** Committing it put chronicle's own
`pre-commit` hook in the path, and the hook runs `vitest run`: **24 files, 314 tests, all passing in
10.6 s** at commit `09d68e5`, against the installed `@modelcontextprotocol/sdk@1.32.1`. That is 16
more tests than the 298 in the September evidence, and it settles a question that had been open since
the SDK bump: the bump does not break the suite.

What that run does **not** supply is coverage or a mutation score — the hook runs the suite, not
`test:coverage` and not `stryker`. So the 59.98% and MSI 36.92 in VERIFIABLE remain **evidence files
recorded 2026-09-12/13 that I did not reproduce**, because the coverage run was stopped for low system
memory earlier in this session and I was instructed not to restart it unprompted. Both could have
moved in either direction across 16 new tests; the direction is probably up, which is exactly the kind
of guess this section exists to refuse.

### STRENGTHS

**Auditability of its own mistakes.** This is the property the repository can stand behind most
strongly, and it is rarer than any of the others. `.claude/ledger.md` is an append-only log in which
a passing suite is treated as suspicious: "A suite that only passes has not shown it can fail", "A
confident number on an untested property is worse than no number", "A gate that has never failed has
not been verified". Each entry is dated, names the wrong belief, and several correct ADRs that had
already recorded a claim as verified. An auditor can reconstruct not just what was decided but what
was believed and when it stopped being true.

**Defence at the right layer.** The isolation boundary moved from client-side `WHERE user_id = …`
into Postgres row-level security bound to `current_user`, and the suite that verifies it was rewritten
to attack a replica of the old policy so that a green result means something. ADR-019's decision to
delete the `raw_content` column rather than default a flag to off is the same instinct applied to
privacy.

**Composability.** Zero import cycles under an error-level rule, with the layer map written down and
the composition roots named.

### WEAKNESSES

**BOUNDED — "Spreading Boundary", and the risk is concrete.** No declared limit, no blocking gate,
one advisory hook that cannot fail and miscounts. `src/mcp/server.ts:37` is a 636-line function and,
per `Status.md:52-55`, the same file holds 581 of 1,684 mutants with no unit coverage, "because the
one real defect found today lived exactly there". Unbounded size and the largest untested block are
the same file. The risk is that the next defect lands in the same place and the same instruments miss
it again.

**VERIFIABLE — "Unbound Spec" at the integration layer.** A 24 : 0 : 0 pyramid with the real
integration tests parked in `scripts/`, runnable only by hand and, for three of them, only with a
live credential. The repository has already been burned by exactly this: 168 green unit tests while a
teammate's shared memory was unreachable in production, twice over, because the test double returned
convenient shapes. The risk is that the suite stays green through the next driver-boundary change.

**Documentation freshness — the derived document contradicts its sources.** `Status.md` claims
41.17% coverage, MSI 20.67 and 119 tests; the evidence files it cites record 59.98%, 36.92 and 298.
The real numbers are *better* than the stale claim, which is why nobody noticed. A status document
that is wrong in the flattering direction is still wrong, and it is the first thing a new reader
trusts.

### PRIORITIES

1. **Declare the limits (prerequisite for everything in BOUNDED).** A `## Quality Gates` section in
   `docs/spec.md` with this repository's real intended values, and `max-lines` / `max-lines-per-function`
   as eslint errors with recorded exemptions for the four existing offenders. Until a limit is
   declared, no instrument in the harness can measure the gate and no hook can enforce it. Small
   effort, unblocks the rest.
2. **Close the `prepublishOnly` advisory hole.** One line; it is the only finding that can ship a
   known-vulnerable dependency to npm, and v0.5.0 is next.
3. **Give the integration layer a home.** Move the five `scripts/verify-*.mjs` into
   `tests/integration/`, skipped without credentials, so the pyramid reports what exists. This is the
   prerequisite for VERIFIABLE moving at all; coverage percentage is not the binding constraint, layer
   coverage is.

Self-describing is already strong enough not to be first here, which is unusual and is the reason the
other properties are legible at all.

### BLIND SPOTS

- **Coverage and mutation did not run.** The suite itself did — 314 passing at `09d68e5`, see §2 —
  but the percentage and the mutation score are still from evidence dated 2026-09-12/13, because the
  `pre-commit` hook runs `vitest run` and not `test:coverage` or `stryker`. Everything numeric under
  VERIFIABLE inherits that staleness; the pass count does not.
- **Nine instruments returned `not measured`** and I substituted hand-run equivalents for `tsc` and
  `eslint` only. `madge`, `jscpd` and `knip` are genuinely not installed, so duplication, dead code
  and an independent cycle check are unmeasured. `gitleaks` is not installed; my secret scan was a
  regex pass over `src/` and `scripts/`, which is weaker.
- **CI branch protection, required reviewers and GitHub repository settings** live outside the repo
  and were not provided. "PR density" below is inferred from merge commits, not from the API.
- **Railway configuration** — roles, grants and the live policy set — was verified by the repository's
  own scripts on 2026-10-26 but is infrastructure I cannot read from here.
- **The dashboard and the MCP surface were not exercised as a user.** `smoke` reports 12/12 from a
  recorded run; I did not reproduce it.
- **`src/dashboard/server.ts:102`'s 393-line `dashboardHtml`** emits HTML I did not review for
  injection; the dashboard binds locally, but that is an assumption I did not verify.

## SECTION 7 — TEAM HABITS (65 commits, the full history)

**PR / review density.** 5 merge commits and 6 merged pull requests (#1–#6, all authored and merged
by the same person) against 65 commits. Direct commits to a working branch are the norm; the PRs
carry the substantial changes. **Effective external review: zero.** No commit in this history has a
second reviewer, and `.github/CODEOWNERS` does not exist in this repository.

**Commit-size distribution** (`git log -200 --format=%H --numstat`):

```
n = 65    median 117    p90 3,981    max 26,841    over 400 lines: 19 (29%)
```

The median is healthy and the tail is not. 19 commits over 400 lines, with a p90 of nearly 4,000,
means roughly a third of the history cannot be reviewed as a unit. The largest are the GS adoption
and spec-writing commits, which are bulk document additions rather than tangled code — but
`feat(security)` and `feat(scopes)` are both in the tail and are code.

**AI-introduced bug rate — measurable and unusually well documented.** No commit in this history is a
`revert`. The hot-fix pattern instead appears as a named correction: ADR-023 recorded an RLS fix that
ADR-024 then found to be wrong (string surgery on an irreversibly sanitised role name), and the
isolation suite went 12/12 → 12/13 → 15/15 across three corrections in two days. `.claude/ledger.md`
records **fifteen** such corrections between 2026-09-12 and 2026-09-16, several of them the same
lesson learned twice: "Three iterations of the same lesson in one session: one sample, then a
mislabelled p95, then a model that only held on one host." A reasonable estimate is **one
corrected-wrong-belief per two working days in that period**, which is high, and every one of them
was caught and written down rather than silently patched. The rate is a measure of how hard the work
was and how good the instrumentation is, not of carelessness.

**Regression coverage.** Strong in the recent window, absent before it. The 2026-09-12 to 09-16 fixes
each landed with a test that reproduced the defect first — `sqlite-decay-parity.test.ts` for the
duplicated decay formula, `local-migration.test.ts` for the `IF NOT EXISTS` migration hole, the
rewritten isolation assertion for the RLS policy. Earlier fixes have no accompanying test.

**Collaboration graph / bus factor: 1.** All 65 commits are one person under three identities — 56
`Juan Carlos Ghiringhelli <jcghiri@gmail.com>`, 6 `JC <jcghiri@gmail.com>`, 3
`Ghiringhelli, JuanCarlos <juancarlos.ghiringhelli@solera.com>`. Every file has effectively one
author. Knowledge is concentrated completely, and the mitigation in place is documentary rather than
social: the sentinel tree, the ADRs and the ledger exist so that a stateless reader — human or model

reason this audit could be done at all.

**Co-change coupling.** The tightest pairs are `docs/adrs/active/ADR-0NN` with the `src/` or

second Node version in CI caught the `engines` segfault; a real Postgres caught the driver-type

lesson about itself is written at `.claude/ledger.md:33-37`, and the structural fix — making those
instruments part of the gated suite — has not been made.
