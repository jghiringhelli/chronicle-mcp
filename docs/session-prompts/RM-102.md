# RM-102 — Test `sync.ts`: the five assertions named in EDR-003

**Load:**
- `docs/edrs/EDR-003-cloud-sync.md` — the contract, the conflict policy, and the Verification
  section, which names the five assertions
- `docs/adrs/active/ADR-010-fold-axon-coordination-into-chronicle.md` §3–§4
- `src/services/sync.ts`
- `.claude/standards/testing.md` — test naming, the doubles taxonomy
- **Do NOT load:** `coordination-service.ts` (that is RM-103), `docs/chronicle-spec.md`

**Scope:**

`src/services/sync.ts` is 522 lines carrying four sync passes, a conflict policy and a cursor,
with **zero tests**. Write the five assertions EDR-003 names. Nothing else.

1. `skipped: true` and **no** writes when `config.railwayUrl` is unset — and the same for
   `syncCoordination` when `teamId` is unset. Absence of configuration is a normal state, never
   an error (NFR-09). This is the assertion that protects every local-only install.
2. Push discards a stale row: a remote row with a newer `last_accessed_at` is not overwritten.
3. Pull skips a local row that is newer than the remote one.
4. `buffer`-tier memories are never pushed.
5. The cursor advances exactly once per pass, and a first run (no cursor) syncs from epoch.

Use a **fake** `sql` client — a working in-memory stand-in, not a mock with call expectations
(`testing.md`, doubles taxonomy). Local SQLite is a real `:memory:` database, as in
`sqlite-memory-repository.test.ts`. Test names are behaviours:
`skips_every_pass_when_no_railway_url_is_configured`.

**The cursor asymmetry.** EDR-003 flags that `syncMemories` pulls using `cursor.last_push_at`
while `syncInsights` uses `last_pull_at`, and calls it a suspected defect. **Pin the current
behaviour in a test first**, with a comment naming EDR-003. Then, if the test makes the defect
undeniable, open a `docs/decisions/` post-mortem and fix it in a separate `fix(sync):` commit
with the regression test leading.

**NOT IN SCOPE:**

- **Changing `sync.ts`.** This is a characterisation task: write tests against what is there. The
  one exception is a change required to make the unit testable at all (injecting the `sql`
  client) — and if that is needed, it is a `refactor(sync):` commit of its own, landing before
  any test commit, with no behaviour change.
- Fixing the cursor asymmetry here. Pin it, then decide.
- The `conflicts` counter, which EDR-003 records as always `0`. Do not build a test that
  asserts a number the code never increments.
- Any network call. A test that reaches a real Postgres is not a unit test.

**Acceptance:**

- [ ] Five assertions, one test each, named as behaviours
- [ ] No network access in any test; `sql` is a fake, local SQLite is `:memory:`
- [ ] The cursor-asymmetry test cites EDR-003 in a comment
- [ ] `pnpm run test:coverage` passes and coverage on `src/services/sync.ts` rises from 0
- [ ] `pnpm run test:mutation` — surviving mutants inside the five tested paths are either killed
      or recorded in the EDR with a reason
- [ ] EDR-003's Verification section is updated to say what is now pinned
